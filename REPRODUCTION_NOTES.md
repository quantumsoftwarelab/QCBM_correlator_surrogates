# Reproduction conventions and unresolved legacy issues

The default figure command reconstructs the archived plots from their numerical inputs. It does **not** silently correct a scientific definition, replace the original runs, or treat successful rendering as validation of every claim in the paper.

## Issues found while consolidating the notebooks

1. **Figure 8, panel d: loss label/input mismatch.** `diff_losses_plot.ipynb` loads `histories_1d_ising_tv.pkl` but labels it `SQE`. The training notebook defines TV as half the L1 distance and squared Euclidean as a different loss. The reference reproduction keeps that input and published label. The archived histories have 20 runs of 800 iterations per order, while the paper caption describes ten initializations. A corrected SQE figure needs an explicit decision to substitute the separate SQE experiment.
2. **“Hamming” MMD filenames do not match the implemented distance.** The relevant MMD classes use squared distance between integer state indices, not Hamming distance between bitstrings. The shared fresh-training loss preserves this formula and names the convention in its docstring. At the small bandwidths used here the matrix is effectively diagonal. ANOVA experiments use the saved ANOVA matrices. Do not infer kernel parameters from filename suffixes alone: the source filenames, notebook values and panel labels differ.
3. **Figure 9: reference distribution and caption differ.** The plot computes KL between the deployed order/subset model and the corresponding fully constrained model output (`k=6`), paired by run index. It does not use the DMRG/gene target distribution as its KL reference. The code uses ten stored runs and four circuit families in two rows; the caption describes 100 experiments and two families. The archived eight-panel plot determines the reproduction layout.
4. **Figure 10 batch-training objective has a summation-axis issue.** In `multi_batch_RkOS.ipynb`, `final_signs` has shape `(z_batch, x_batch)`. The code multiplies by one surrogate correlator per row and sums over axis 1, leaving one value per correlator. It compares these values with target probabilities indexed by the correlator support masks. This is not the intended reconstruction of a probability at each sampled bitstring. `train_batches.py` explicitly preserves this historical objective and initialization to expose the convention; it is not a corrected probability estimator. The supplied KL summaries are sufficient to replot Figure 10, but a corrected experiment requires new runs and cannot be asserted to reproduce the existing curves.
5. **Figure 11: averaging and counts differ between panels.** TN records contain ten 200-step runs; the PPS summary contains five 500-step runs for each available `(k,h)`. The plot selects the largest stored `k` and shows the first 200 iterations. TN bands use arithmetic mean and standard deviation. PPS bands use `exp(mean(log loss) ± std(log loss))`. These are deliberately not collapsed into one averaging rule because that would change the published values.
6. **Figure 12: legacy MSE normalization and indexing.** Plotting sums stored per-run contributions, some of which already include division by the number of experiments. Training cells use cumulative counts `N_p` in the denominator. Some target-correlator slices index a vector containing identity using bounds constructed for a vector without identity; TN code also slices exact-order predicted correlators. The reference figure uses the saved MSE dictionaries and does not apply a second averaging or relabel the results as newly verified exact-order MSE. Fresh `train.py` saves raw predicted correlators and probabilities, not another copy of this ambiguous MSE calculation.
7. **Figures 7, 14, and 15: preserve plotted transfer-matrix quantities.** The shared RMPS implementation evaluates the same two-by-two transfer products and boundary sum as the notebooks. Figure 7 retains the source's normalization, `D=0` endpoint, and asymptotic guide lines. Figure 14 plots the purity-like transfer result directly; the source labels it Renyi-2 entropy but does not apply `-log`. Figure 15 enumerates projector/identity placements, despite its bitstring labels. These labels/conventions are retained for traceability, not reinterpreted as corrected formulas.
